# 安全设计与限制

## Windows 登录方式

Windows 端注册一个原生 Credential Provider，由系统 LogonUI 调用。它不会更改 Windows 的锁屏背景、密码输入框、PIN、Windows Hello，也不会禁用其他凭据提供程序。

蓝牙认证成功后，凭据提供程序通过 Windows 官方的 `KERB_INTERACTIVE_UNLOCK_LOGON` 格式提交已配置账户的密码。Windows 仍通过系统身份验证机制决定是否允许解锁。因此，首次配置必须输入有效的 Windows 登录密码，且密码修改后需要重新保存。

当前实现面向传统本地 Windows 账户和 Active Directory 域账户。无密码 Microsoft 账户、Windows Hello 专用登录、Microsoft Entra ID、智能卡、特殊单点登录或安全策略限制的账户可能无法使用。

Windows 10/11 可能使用 `CPUS_LOGON` 场景处理解锁。程序会检查当前活动控制台已经存在用户名、域名均匹配的 **锁定** 会话，并且仅在认证成功后继续；关机后的首次登录、注销后的登录、其他用户的登录会话及远程桌面会话不属于目标场景。

## Windows 凭据的保护

- 保存设置前，使用 `LogonUserW` 检查 Windows 账户密码是否有效。
- 使用 Windows DPAPI 的 `CRYPTPROTECT_LOCAL_MACHINE` 选项加密密码。
- 将加密数据存放于 `%ProgramData%\Kenvix\BluetoothUnlock\configuration.dat`，文件夹的访问控制列表限制为 `SYSTEM` 与本地管理员。
- 每次解密和提交密码后尽快清除工作内存中的明文内容。
- 高安全性模式绑定公钥；新手机必须重新核对指纹。

管理员权限和 SYSTEM 权限能够访问本机的加密配置。计算机遭到管理员级恶意软件控制，或攻击者已经取得操作系统的管理权限时，无法仅依靠 DPAPI 阻止其访问登录凭据。启用 BitLocker 可以降低设备丢失后离线读取数据的风险。

## 安全等级

**低安全性模式**：仅检查蓝牙设备广播、RSSI、地址及 Windows 配对状态。设备标识可能被复制，广播也可能被模拟；适用于便利性优先的个人设备，不建议用于含有敏感数据的电脑。首次使用前必须在 Windows 蓝牙设置中将目标设备配对，且目标设备必须能被 Windows 持续发现。

**高安全性模式（自动）**：手机用 Android Keystore 中的 ECDSA P-256 私钥对随机挑战签名，Windows 使用绑定公钥验证。能够抵御仅伪造蓝牙设备地址或重放旧认证响应的攻击。手机靠近电脑且应用的蓝牙服务运行时可以自动完成验证。

**高安全性模式（手动确认）**：在以上挑战认证的基础上，每次还要求在手机上使用系统生物识别或锁屏密码确认。它可以减少随身携带手机时意外解锁的情况。

## 仍然存在的风险

- **中继攻击**：攻击者可以转发真实手机与电脑之间的蓝牙通信，挑战认证本身无法测量物理距离。RSSI 只是一种粗略的接近程度指标，会受到人体遮挡、墙壁、天线方向和发射功率影响。
- **手机失窃或被入侵**：自动模式下，能够持续使用手机蓝牙服务的攻击者可能触发解锁。应启用手机锁屏密码；敏感场景选择手动确认。
- **本机账户密码变更**：保存的凭据需要更新，否则 Windows 会拒绝登录。
- **蓝牙适配器限制**：部分 Windows 蓝牙驱动程序在 LogonUI 或 SYSTEM 上下文中无法进行完整 BLE GATT 通信。此时需通过真实 Windows 设备验证，不能仅凭跨平台协议单元测试确定兼容性。
- **Android 后台限制**：厂商电源管理策略、蓝牙关闭和权限撤销可能使外围设备广播停止。应用使用前台服务与常驻通知，但无法承诺在所有手机上永久运行。
- **软件安装风险**：Credential Provider DLL 进入系统登录进程，应先通过自动构建和真实设备测试，再在日常使用的计算机上安装。首次安装前建议创建系统还原点，并保留可用的密码或 PIN 作为替代登录方式。

项目未更改系统已有登录方式，也未对 Windows Credential Provider 注册表添加过滤规则。任何蓝牙解锁失败都应保留系统原有的密码/PIN/Hello 登录功能。
