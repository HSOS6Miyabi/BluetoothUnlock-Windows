# 蓝牙通信协议（版本 1）

此文档描述 Windows 与 Android 之间的蓝牙低功耗（BLE）GATT 数据格式。连接时 Windows 为 GATT 客户端，Android 为 GATT 服务端。

## UUID

| 名称 | UUID | 方向 |
|---|---|---|
| 主服务 | `5b0d6834-e3e9-48c0-977a-877a5d1f2b45` | Android 广播 |
| 手机公钥 | `5b0d6835-e3e9-48c0-977a-877a5d1f2b45` | Windows 读取 |
| 解锁挑战 | `5b0d6836-e3e9-48c0-977a-877a5d1f2b45` | Windows 写入 |
| 认证结果 | `5b0d6837-e3e9-48c0-977a-877a5d1f2b45` | Windows 读取 |

所有数据均使用二进制表示；多字节整数仅存在于 ECDSA 标准编码内部。

## 公钥与绑定

Android Keystore 生成一对 `secp256r1` 椭圆曲线密钥。公钥以 65 字节的 SEC1 未压缩点格式表示：`0x04 || X(32字节) || Y(32字节)`。Android 私钥始终保存在 Keystore 中，不通过蓝牙传输。

Windows 设置程序读取手机公钥，计算 `SHA-256(公钥)`，在界面上展示前 8 字节的 16 位大写十六进制指纹。用户必须将该指纹与 Android 页面显示的指纹核对一致后才能保存新的绑定。Windows 在本机保存完整的公钥。

## 一次解锁的过程

1. Windows 侦测到符合信号强度要求的 BLE 广播，并检查服务 UUID。
2. Windows 建立 GATT 连接，读取手机公钥，并与本机保存的 65 字节公钥逐字节比较。
3. Windows 通过系统安全随机数生成器生成 32 字节 nonce。为了兼容默认 23 字节的 ATT MTU，Windows 分两次写入 17 字节挑战分片。
4. Android 将 `ASCII("KENVIX-BLE-UNLOCK/v1:") || nonce` 作为待签名消息，使用 `SHA256withECDSA` 签名。自动模式会立即签名；手动模式要求用户先通过系统的生物识别或锁屏密码认证。
5. Windows 读取“认证结果”特征值。若状态为成功，则按 ASN.1 DER 解码 ECDSA 签名，并验证其与当前 nonce 及已绑定公钥匹配。
6. Windows 再次确认当前确实存在匹配的锁定会话。如果在身份验证结束时仍能收到设备广播，还会重新检查信号强度。部分 Android 手机在 GATT 连接期间会暂停广播；此时高安全性模式依赖刚刚成功完成的蓝牙连接及随机挑战认证，并使用认证前满足阈值的 RSSI 检测结果。

## 挑战与响应的数据格式

完整挑战为 33 字节：`0x01 || nonce`，其中 nonce 为 32 字节随机数。为了兼容默认的 BLE ATT MTU，Windows 实际以两次独立的 GATT Write Request 发送挑战，每次只写入 17 字节：

| 写入次序 | 第 1 字节 | 后续 16 字节 |
|---|---|---|
| 第一次 | `0x11` | nonce 的前 16 字节 |
| 第二次 | `0x12` | nonce 的后 16 字节 |

Android 按照同一个 GATT 连接设备地址组合两段数据。第一段最多保留 5 秒；第二段未在有效时间内送达时拒绝该挑战。Android 也能够识别完整的 33 字节格式，便于进行协议测试。

响应由 3 字节首部加可选签名组成：

| 偏移量 | 长度 | 内容 |
|---|---:|---|
| 0 | 1 | 协议版本：`0x01` |
| 1 | 1 | 认证状态：`0` 等待，`1` 成功，`2` 拒绝 |
| 2 | 1 | DER 签名长度，等待与拒绝时为 `0` |
| 3 | 可变 | ASN.1 DER 格式 ECDSA 签名，成功时长度为 8–72 字节 |

正常情况下，P-256 ECDSA 签名为约 70–72 字节。Windows 进行完整长度检查、DER 格式检查以及 ECDSA 验证。

Windows 每次解锁都生成新的 nonce；Android 在发起挑战后最多保留 30 秒的响应结果，服务重启或蓝牙连接断开时会清理内存中的请求。Windows 最长等待 25 秒。超时、密钥不匹配、拒绝、数据格式错误或签名验证失败都会导致本次认证失败。

## 广播名称与列表驻留

Windows 会合并同一 BLE 地址收到的主广播与扫描响应：有名称的设备显示原名称；只有专用服务 UUID 而没有名称的设备显示“解锁服务设备（名称未广播）”，其他没有名称的设备继续隐藏。列表保存最近一次信号，设备短暂离线时仍显示约 3 分钟，并注明这是上次测到的信号。连续 6 个 30 秒时间段没有新广播后会移除对应记录。显示列表的历史记录不能触发解锁，验证解锁信号时必须使用最近 4 秒内的新广播，并符合原有认证要求。

## 信号强度和设备识别

Windows 使用系统 BLE 广播观察器读取 RSSI，允许配置的最低值为 `-100` 至 `-35 dBm`。发起认证前必须收到最近 4 秒内的至少两次广播采样。认证完成后会再次检查会话状态；如仍有新广播，则再次核对 RSSI。高安全性模式允许已经通过挑战认证的手机在 GATT 连接期间暂停广播。低安全性模式始终要求新近收到的广播。

高安全性模式以公钥识别手机，因此 Android 临时蓝牙地址变化时仍可认证。低安全性模式使用本机已配对设备的蓝牙地址及系统配对状态，不参与上述挑战认证。

## 版本演进

首部中的 `0x01` 是协议版本。任何一方收到未知版本都应拒绝请求。未来增加能力时应分配新的协议版本，并保留旧版本兼容性测试。
